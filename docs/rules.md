# 解码、注入、失效、热加载与多路规则

实现位于 `internal/gateway`，位编解码位于 `internal/canbus`。

## 帧解码

`HandleFrame` 按固定顺序判定：

1. `UNKNOWN_MESSAGE`：报文 ID 不在当前定义。
2. `TRUNCATED_FRAME` / `LENGTH_MISMATCH`：数据长度小于 / 大于定义 DLC。
3. `TIMESTAMP_REWOUND`：同一报文 ID 的时间戳早于上一帧被接受时间；相等时间戳允许。
4. `MUX_LAYOUT_MISSING`：复用器选择值下没有任何可解码分支信号。
5. 全部通过后更新复用器和当前分支；普通信号始终在当前帧中更新。

拒绝帧不创建、不覆盖任何状态。状态包含原始值、物理值、单位、更新时间、接收时间和枚举标签。

## 按信号注入

入口：`Gateway.Inject(Injection{MessageID, Values, Timestamp, Seq})`。

注入先构造完整帧，再走同一个 `HandleFrame`，因此解码、校验、统计和状态更新路径完全一致。

- 默认值：某报文从未收到过帧时，初始数据为全 0，即未写入信号位的原始值为 0。
- 完整覆盖：每次注入对本次明确给出的信号是完整覆盖——写入前先清零该信号自身占用的位，
  因此同一信号先写大值（如 800）再写小值（如 100）不会残留高位，回读在半个量化步长内等于写入值。
- 保持语义：之后注入时，先复制该报文上一帧被接受的数据，只改显式列出的信号位；
  没有给出的信号一律保持上一帧被接受时的原始位（包括复用报文里未被选中的旧分支位）。
- 复用布局：不给出选择值时，沿用上一帧被接受帧中的选择器原始位；从未收到帧时按默认值取 0。
  切换选择值时不清空其它分支的原始位，只覆盖明确写出的信号；旧分支位继续保留在帧里，
  查询时按当前选择值判定为 `INACTIVE`，不参与当前解码结论。
- 只写普通信号：复用报文只写普通（非复用器、非分支）信号且不给出选择值时可以正常构造，
  只改动写出的信号，选择器与各分支位全部保持。
- 量化：物理值四舍五入到最近原始码值；查询值需落在半个量化步长内。
- 失败原子性：构造失败不产生帧、不进入解码计数，也不污染上一帧数据和已有状态。

注入失败类型：

- `UNKNOWN_MESSAGE`：未知报文。
- `UNKNOWN_SIGNAL`：报文内未知信号。
- `VALUE_OUT_OF_RANGE`：超出定义范围或指定位宽/缩放无法表示。
- `MUX_SELECTOR_INVALID`：明确给出的选择值不是整数，或超出选择器声明范围 / 位宽。
- `MUX_LAYOUT_MISMATCH`：目标信号属于另一个选择值布局。
- `MUX_LAYOUT_MISSING`：选择值下没有任何可写分支布局。
- `TIMESTAMP_REWOUND`：注入时间戳早于该报文上一帧被接受时间。

三类复用矛盾严格区分，互不混淆：选择值本身非法归 `MUX_SELECTOR_INVALID`；
选择值合法但目标信号属于其它布局归 `MUX_LAYOUT_MISMATCH`；
选择值合法且无目标矛盾、但该选择值下没有任何可写分支归 `MUX_LAYOUT_MISSING`。
任何一类失败都在构造阶段返回，不会生成半成品帧，也不会改动该报文上一帧数据、
已有信号状态、时间戳或解码计数；注入与热加载使用同一把写锁，互不干扰。

## 失效与复用状态

查询状态：

- `OK`：在超时窗口内有有效值。
- `TIMEOUT`：超过该信号的超时配置；仍返回最后一次值和更新时间。
- `NEVER_RECEIVED`：定义存在，但从未收到包含该信号的有效帧。
- `INACTIVE`：信号属于复用报文，但当前复用器选择的是其它分支。

`INACTIVE` 与 `TIMEOUT` 分开：切换选择值后，旧分支信号的查询结论始终是 `INACTIVE`，
即使其更新时间已经超过超时窗口也不会报 `TIMEOUT`；其最后一次原始值仍可在状态中查看，
但不表示当前有效。超时只由更新时间决定，且只对当前选中分支和普通信号生效。
定义不存在的报文/信号仍返回 `ok=false`，不与 `NEVER_RECEIVED` 混淆。

## 热加载

`Reload(reader)` 先在锁外完整解析和校验新定义：

- 失败：返回 `dbc.ErrorList`，旧定义、旧状态、上一帧数据和统计继续工作。
- 成功：在写锁内替换整份定义，并清空旧定义下的状态和上一帧数据。
- 并发观察者只能看到完整旧快照或完整新快照。

## 多路总线

`BusRegistry` 在一个进程内维护多条命名总线：

- 每路拥有独立 `Gateway`、定义、状态、上一帧数据、超时配置和统计。
- `AddBus`、`Get`、`MustGet` 按总线名分发；未知总线返回 `UNKNOWN_BUS`。
- `ReloadBus` 只影响指定总线；该路解析失败时其它路和该路旧行为均不变。
- `SnapshotAll(now)` 返回每路状态汇总；结果与逐路调用 `Stats`、`Snapshot` 一致。
- 一路持续收到坏帧只增加该路拒绝计数，不影响其它路查询。

注册表和单路网关各自加锁；多路同时解码、注入、查询、热加载可在 `go test -race` 下验证。
