# can-dbc-signal-gateway-go

一套**完全本地可运行**的 CAN 信号解析与车辆状态维护组件：总线帧由本地确定性帧序列模拟，
信号定义从本地 DBC 文件读取，不依赖真实硬件或外部服务。对畸形定义、异常帧、信号失效与
运行中更新定义，结论稳定、可解释、可复现。

## 结构

- `internal/model` — 报文/信号/状态的不可变数据模型
- `internal/dbc` — 真实 DBC 写法解析、数值表、导入摘要与结构校验
- `internal/canbus` — 帧模型、Intel/Motorola 位编解码、有符号二补码、缩放偏移、拒绝原因
- `internal/cansim` — 本地帧序列脚本与按定义构造帧的 Builder（含截断/未知帧辅助）
- `internal/gateway` — 解码、按信号注入、每信号状态维护、超时/不激活判定、原子热加载、多路隔离（RWMutex）
- `cmd/demo` — 端到端本地演示
- `testdata/demo.dbc` — 示例定义（含跨字节、两种字节序、复用报文）
- `docs/` — 支持子集与边界、解码/失效/热加载规则、本地复现指南

## 快速开始

```bash
go run ./cmd/demo                                   # 端到端演示
CGO_ENABLED=1 go test -race ./...                   # 全部测试（竞态检测）
CGO_ENABLED=1 go test -race ./... -v                # 查看分业务/输入/判定的结构化日志
```

## 关键语义（详见 docs/）

- **非法定义不静默跳过**：一次解析返回 `dbc.ErrorList`，收集全部错误；
  每条带行号、报文、信号与可区分 `Reason`（语法、越界、斜跨字节、位重叠、复用矛盾等）。
- **导入可审计**：`dbc.ParseDetailed` 返回采用的报文/信号、明确忽略的元数据及原因、拒绝位置。
- **数值表可用**：查询同时给原始值、物理值和标签；未收录原始值稳定回退为无标签。
- **异常帧不污染状态**：未知报文 / 长度不符 / 截断 / 非法复用选择值 / 时间戳回退
  各自返回可区分的 `canbus.DecodeReason`，帧被整体拒绝。
- **按信号注入**：明确给出的信号写入前先清自身位（完整覆盖，先大后小不残留），
  其它信号沿用上一帧被接受的原始位，从未收到帧时按全 0 默认；复用报文不给出选择值时
  沿用上帧选择器（无历史帧默认 0），只写普通信号也能构造；选择值非法、布局不匹配、
  无布局三类矛盾分别报错，失败不留半成品；切选择值后旧分支为 `INACTIVE`，不与超时混淆。
- **真实导出写法**：冒号/括号/引号周围无空格、扩展帧 bit31 高位标记 ID、
  有符号信号的负数数值表条目（如 `-1 "err"`）都可原样接入，与常规写法解析等价。
- **失效可配置**：默认超时 + 按信号覆盖；偶发丢帧不误判，持续无更新判 `TIMEOUT`，
  来帧即恢复；`NEVER_RECEIVED`、`INACTIVE` 与"信号不存在"严格区分。
- **多路隔离**：`BusRegistry` 按总线名分发帧、注入、查询、热加载和汇总，单路故障不影响其它路。
- **热加载原子**：新定义先完整解析，失败整体拒绝且旧定义继续服务；成功后在写锁内
  一次性替换，并发观察者永远看不到新旧混用。
- **可复现**：不使用墙上时钟；帧时间戳与查询 `now` 均由调用方提供，序列重放确定。
